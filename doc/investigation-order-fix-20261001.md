# 动态调查顺序与可读性修复

用户反馈：动态房间按钮暗字叠暗底，查看第二调查点出现通用请求失败。

源码原因：共享槽位合同要求第一项的 doneFact 为 true 才允许第二项；原 UI 将两项都作为可直接查阅的目标，没有解释前置条件。深色按钮又继承了金色面板的深色前景色。

修复：显式调查 1 / 调查 2；未解锁项显示需要完成的第一项并禁用列表提交；直接走近锁定物件时只显示前置说明，不发送动作。下一步由已提交事实显示具体目标；已读资料可以重看；出口始终可用。按钮明确前景/背景色，锁定态保留可读文字。

验证：追加乱序动作零写入测试、顺序投射测试。真实浏览器使用新建本地合成存档、相同公开源码与真实 RPGJS/SWI，实际走动并完成两项调查，返回资料室；不读取或改变用户存档，不调用模型。线上已有动态房间另做只读规则复演，两项初始均未完成，按顺序均可执行（约 204ms / 195ms）；该检查不冒充线上玩家提交。

浏览器复验：两项完成后刷新，仍回到资料会议室且保留完成状态；重入房间两项显示「已查阅 · 可重看」。390×844 和 320×568 检查按钮对比度、换行、出口可用；浏览器无 error 日志。

本轮不修改规则门槛、数据库、身份、模型总账或云资源。保留玩家已有进度。完整世界无限生成和跨设备账号仍非本次修复范围。
