# 技能跨题材评估：交割之前
## 基线与边界
输入是 baseline 内冻结技能 ZIP、当前正式平台媒体技能、冻结 stateful 引擎和用户确认的金融故事需求。未读取旧游戏源码。本项目作者知道此前失败历史，因此属于带经验的独立新题材复用，不冒充陌生同事 agent 的盲测。
## 验收方法
按需求→资料/角色→素材→空间→互动→存档→结局→发布建立证据；每个缺口记录发现、原因、修复、复验和技能回写。机械检查、真实画面、玩家理解三层单独判定。用户未测试前理解状态为 unverified。
## 待验证
主角图集、现代家具投影、开放大场景、人物介绍与巡游、证据追问、条件谈判、多旅程、所有高频交互、双语手机布局、声画完整。
## 制作日志
- 冻结原包并记录 SHA，独立创建工程。空间模块使用包内 world/distance-motion 等；不复制旧成品。
- 初始能力档案自带 implemented 示例，需要在新项目全部降为 planned，不能照抄为通过。这是默认模板容易造成虚报的风险，后续回写。
- 失败 A：第一版 12 格主角朝向错乱；拆为三个方向任务，侧向站姿仍错，单独生成站姿后装配。保留拒绝版本，正式清单不引用。
- 失败 B：孤立家具合格但同屏桌子过大；主角显示框提高到80、桌宽降到88，保持原图等比。投影与比例必须在场景检查。
- 失败 C：椅子占地挡住桌前接近点；从同一碰撞清单选择合法接近候选并检查所有路径，杜绝渲染与交互双份布局。
- 失败 D：320×568 的首次介绍结束后正文挤掉第二个选项；为 choices 阶段保留可滚动的短正文区，主要话题首屏验收需要覆盖“刚完成介绍”而非只覆盖空白重开。
- 检查器缺口：主角文档允许逐格通过的单任务多帧图，但 audit-hero-sheet.py 把相同任务与源SHA的两个步态一概拒绝；需要验证源裁切矩形与各格实际hash后允许真正不同的格。不能通过伪造源身份绕过门禁。

## 结论与具体回写
v1.45 已回写：能力模板 planned 默认值、主角多格源hash审计、首介绍选项首屏、门洞补片层级、转场等待真实素材、签署证据快照。独立脚本包回归通过，4项主角正负例通过。完整交接包同时包含空间技能、stateful冻结内核、平台媒体与界面流程依赖，排除node_modules、dist和私有发布配置。

发现的运行时缺口已修：移动NPC寻路/接近使用实时位置；离开旧场景的卸载回调不能覆盖新场景落点；读档后的首次移动也解锁音乐；坏档不能静默覆盖。新文档附带任务、source/crop SHA和选定原图，接收端能复算而非依赖本机素材路径。

媒体实测：多个小图任务在约10–25秒完成，但早期下载无超时把墙钟拉长数分钟；运行脚本已将服务结果先持久化，再对下载设连接/总超时，重复执行复用成功任务。大头像图集两次终态失败，拆小批生成成功。素材生成速度、下载速度、裁切装配和最终准入时间必须分别记，不能只报平台 timing_ms。主角多轮修正说明素材首轮稳定性仍弱，不应承诺一键生成完成。

## 交接成熟度
- 包完整：已打包依赖、独立参考、模块、原始合同及检查器，临时目录回归通过。
- 跨题材实际复用：本项目四场景与完整章节通过，未查看旧成品源码；并非所有包内模块直接复用，world/distance-motion实际消费，其余合同行为由新产品壳实现。
- 陌生同事盲测：未完成。作者熟悉历史问题，不能声称等同独立接收方。
- 未覆盖：运行时新房间媒体生成、账号云存档、多人、实时模型自由对白。本章明确不提供，不把未测能力算已验证。
- 体验待外部证据：投资人是否自然理解三项判断、实际时长、真机触控与全曲听感。

综合判断：可以交接为带验收门禁的制作工具包；还不能称为一次生成即可稳定交付高保真的自动化方案。用户试玩之后应按具体失败修正合同，而不是继续堆叠空泛“加强审核”。

## 第二轮：优先完成游戏
用户要求暂不处理平台入库后，再查到的具体缺口：旅程目录切换可能丢最近脚点；回访旧场景让剧情时钟倒退；摇杆没有位移反馈；资料齐全后缺少入口指引；结局后角色没有回应。已分别补齐存档检查点、单调作者时间、死区与跟手手柄、核对提示、按角色/决定的结局对白。已签署条款同时增加领域层不可改写保护。前次“已完成”结论偏早，自动通关没有覆盖这些体验与中断状态。

## 2026-09-21 第二轮视觉再认证
用户否定第一版后，本项目回看旧街真实画面并重做纽约国际团队、主角动作、四套功能场景与英文语境。第二轮证明技能的空间、叙事和 UI 合同可支撑成品，也证明原美术准入会在“提示词正确、素材生成成功”后误放行低质量组合。

本轮新增的可移植门禁：产品语言、受众和所在地分开记录；英文最终字符串拒绝旧机构、姓名与货币残留；场景按业务功能组合而非复用同一桌椅；运行时直接消费已验收接近点，且同时验证可走、可从上一目标到达、落在真实互动半径内。两尺寸完整顺序通关成为家具改版后的阻断门禁。

本轮运行时回归暴露出更基础的技能缺口：此前“RPG-JS 式”没有约束真实 RPGJS。技能现改为直接移动的正交探索默认使用 RPGJS + CanvasEngine + PixiJS，React/DOM 只承担剧情与界面。Tiled 地图即使由共享模型计算碰撞，也必须保留 objectgroup；发布前同时检查 TMX 结构、房间玩家/事件同步和 Pixi 玩家/事件纹理。缺一项时禁止用“地图已加载”宣称渲染通过。

第二轮后用户又发现 NPC 与主角的感知大小和风格不同，说明此前“同显示框 + 成人高度容差”的演员准入仍会误判。旧 NPC 签收已撤销并重做：主角 accepted 后，五名 NPC 强制沿用主角逐方向单帧的生成粒度、方向参考、透明化和装配流程；逐人保存主角相邻站位截图。同时把可见宽度、头部宽高、肩宽、描边和像素密度加入门禁，明确相同数值高度不等于相同感知体量。该规则已写回 `art-admission-gate.md` 与技能主流程。

当前项目在修正演员组并复验后可标为跨题材实际复用通过；技能包仍不能承诺陌生 agent 一次生成高保真。下一次交接前需重新打包本轮参考、规则和测试，并完成陌生同事的小切片复验。

## 2026-09-21 主角步态受控实验

真实试玩再次证明“运行时确实切换三帧”不等于“人物确实在迈步”：旧后向 motion A 的腿部轮廓和 stand 太接近，形成滑行感。针对同一身份、同一方向生成 10 张平台候选后，采用已通过的相反支撑帧作为 edit 参考、要求交换屏幕前后脚，成功率和身份稳定性都优于从站立帧开始。实验数据、十张原图和逐项判定见 `doc/gait-generation-study.md`。

这条失败已回写主角门禁：正式检查必须在装配后的实际显示高度比较 motion A、stand、motion B 的下肢轮廓；纹理 ID、hash 或帧索引不同都不能代替视觉步态验收。

## 2026-09-22 玩家复测后的三项技能缺口

玩家确认人物造型方向已经达到可保留水准，但指出人物姿态、家具输出和房间外墙仍不稳定。这不是三处孤立修图问题，而是原技能只有说明文字、缺少生产清单和阻断检查。

当前主角 12 格运行图集由 9 张平台生成的完整单姿态图装配：下、侧、上各 3 张，另一侧由已生成侧向三帧整帧镜像。它不是一次生成的十二姿态图。逐张生成保护了人物造型，但此前没有强制姿态家族的来源关系，导致独立单图动作可能彼此不连续。技能现增加 actor pose plan：每个生成方向先验收 seed contact，再以该完整图 edit 出 opposite contact；禁止九张互不相关的单图直接拼成正式图集。

家具方面，当前游戏大量使用 45° 斜视正投。单件效果较稳定，但透明角、前后遮挡和复杂碰撞成为房间主流。技能现将轴向斜俯视正投设为桌、柜、床、工作台和成组家具的默认主方向；45° 只能作为 accent，默认数量不超过三分之一、footprint 面积不超过四分之一，每个功能区最多一件，并要求多个矩形或多边形碰撞。

房间外框方面，旧街已经实证 `北墙 → 侧墙 → 人物 → 南墙`，北端侧墙覆盖北墙、南端南墙覆盖侧墙，并包含墙帽、立面、墙脚、短阴影和侧墙内缝。该知识此前存在参考文档，却没有成为新项目的必交结构。当前金融游戏的预烘焙地图没有完整满足新厚墙门禁，因此保留为本轮已知视觉欠账，不能作为墙体能力已验证样本。技能新增 scene visual contract 和检查器，后续房间缺少独立北/侧/南层、四角关系或两尺寸实景证据时不能标高保真。
